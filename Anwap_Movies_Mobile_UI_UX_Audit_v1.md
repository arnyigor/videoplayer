# Anwap Movies — аудит мобильного UI/UX и план переработки

**Дата:** 22.10.2026  
**Платформа:** Android, Jetpack Compose / Material 3  
**Тип продукта:** Netflix-подобный каталог фильмов и сериалов  
**Исходные данные:** семь предоставленных скриншотов (главная, фильмы, фильмы с фильтрами, сериалы, Моё, история, поиск).  
**Ограничение:** аудит по изображениям, без запуска приложения и инспекции исходного кода; не подтверждены жесты, производительность, состояния загрузки и детали плеера.

## 0. Основной вывод

Сохранять структуру из пяти вкладок, тёмный интерфейс, двухколоночный каталог и горизонтальные ряды. Не переписывать приложение заново. Главное — согласовать цветовые токены, пересобрать информационную архитектуру главной/истории/поиска, выровнять карточки и проверить системные insets.

## 1. Аудит палитры

По выборочным пикселям скриншотов:
- Основной фон `#000014`.
- Навигация `#00001C`.
- Активный голубой `#00AFFE`.
- Выбранный сиреневый `#E8DEF8`.
- Фиолетовый для поиска/прогресса около `#B6A0FF`.

Два несвязанных активных цвета выглядят как разные дизайн-системы. Рекомендуется оставить фиолетовый как **единственный брендовый акцент**:

| Token | HEX | Использование |
|---|---|---|
| `background` | `#0B0C12` | Основной фон |
| `surface` | `#191B25` | Навигация, контейнеры, карточки |
| `surfaceElevated` | `#252835` | Меню, попапы, модальные панели |
| `primary` | `#B6A0FF` | Активные вкладки, прогресс, выбранные состояния |
| `onPrimary` | `#101018` | Текст на `primary` |
| `onSurface` | `#F5F5FA` | Главный текст |
| `onSurfaceVariant` | `#B8BBC9` | Вторичный текст |
| `outline` | `#666978` | Границы/обводки невыбранных фильтров |
| `error` | `#FF7180` | Ошибки и опасные действия |

Это предлагаемые цвета, их необходимо проверить на контрастность. Не окрашивать все контролы фиолетовым: главный CTA «Смотреть» можно оставить белым с тёмным текстом.

**Приёмка:** одинаковые selected/pressed/disabled states в NavigationBar, chips, buttons, progress; нет голубого акцента внутри фиолетовой темы; основной текст ≥4.5:1, значимые графические контролы ≥3:1.

## 2. Главная — скриншот 1

**Есть:** бренд, верхние действия, «Продолжить просмотр», «Новинки», нижняя навигация.  
**Проблемы:** `[DEBUG]` в названии; дублирование поиска (верх и вкладка); сортировка на главной; карточки продолжения просмотра вертикальные и занимают много высоты; мало визуального разделения секций.

**Правки:**
1. Убирать `[DEBUG]` в non-debug flavor; не полагаться на имя debug-сборки как на дизайн.
2. Оставить компактный заголовок/логотип, убрать дублирующиеся действия. Главное меню с тремя точками — только если есть нужные действия.
3. «Продолжить просмотр» превратить в ряд карточек 16:9: thumbnail, название, `SxxEyy` для сериала, «осталось N мин», полоса прогресса 3–4 dp.
4. «Продолжить просмотр» разместить перед длинным Featured для возвращающегося пользователя; если истории нет — скрыть секцию и вывести Featured.
5. Featured не растягивать на весь экран: компактный постер/фон + название + одна первичная кнопка.
6. «Новинки», «Популярное», «Для вас», «Сериалы» выводить только при наличии данных.
7. Горизонтальные отступы ~16 dp, межсекционный ~24–32 dp, заголовок/ряд ~8–12 dp.
8. После перехода в детали/плеер возвращать прежний row index, item index, позиции LazyRow и LazyColumn.

**Приёмка:** при возвращении из карточки остаётся позиция; над нижней навигацией нет перекрытого последнего элемента; переход к продолжению просмотра не требует лишнего открытия каталога.

## 3. Каталог «Фильмы» — скриншоты 2–3

**Положительное:** два постера в ряд, простой заголовок, разделённые фильтры, читаемые изображения.

**Недочёты и правки:**
1. Невыбранные фильтры сейчас низкоконтрастные и выглядят disabled. Сделать читаемые `label` и `outline`, а реальные отключённые состояния визуально отличать.
2. Сортировку («Новинки / По рейтингу / По алфавиту») убрать из полной строки в кнопку `Сортировка: Новинки ▾` или компактный dropdown/BottomSheet.
3. Жанры сохранить в одном горизонтальном `LazyRow`. Не делать `FlowRow` с переносом строк на малом экране.
4. При смене жанра гарантировать полностью видимый выбранный chip; устранить обрезание активного элемента.
5. Для постеров использовать единое отношение 2:3, скругление 10–12 dp, два текстовых уровня: название 14–16 sp, год 12–13 sp; заголовки до 2 строк.
6. Информационный футер каждой карточки делать одинаковой минимальной высоты, чтобы строки сетки были ровными.
7. Предусмотреть пустой результат, ошибку сети, skeleton-загрузку, пагинацию, возврат со страницы деталей с сохранением фильтров и положения.
8. Не помещать рейтинг IMDb, жанр, длительность и лайки сразу на карточку — оставить их для деталей.

**Приёмка:** 320/360/393/412 dp — никаких обрезанных выбранных фильтров и названий, кроме оговоренного многоточия; grid равномерный; статус сортировки виден.

## 4. Каталог «Сериалы» — скриншот 4

Переиспользовать те же компоненты что и для фильмов, а не отдельную вариацию. Визуально заметно, что в прокрученной строке жанров слева видна обрезанная часть слова. Выбранный жанр «Боевики» виден, но положение строки не должно ощущаться случайным.

Отличия сериалов в **данных**, а не в сетке:
- единый вертикальный постер;
- в деталях — сезоны, серии, `SxxEyy`, состояние просмотренности;
- в «Продолжить» — конкретная серия и её прогресс.

## 5. Нижняя навигация — все экраны

Пять вкладок **Главная / Фильмы / Сериалы / Моё / Поиск** соответствуют привычному паттерну Material 3 для компактных экранов; структура удачная. Доработки:
1. Единый цвет активного состояния — `primary`, без голубого при сиреневых chips.
2. Проверить крупность и читаемость подписей (ориентир 12 sp), размер иконок 22–24 dp, кликабельность ≥48 dp.
3. Ввести согласованный selected indicator (возможно, мягкая подложка вокруг иконки), избегать крупного эффекта во всю ширину.
4. Для каждой вкладки хранить отдельный back stack и scroll state; повторное нажатие активной вкладки может вести наверх по явно заданному сценарию.
5. Правильно обработать edge-to-edge и gesture/three-button nav; не применять дважды navigationBarsPadding и Scaffold innerPadding.
6. Скрывать навигацию в полноэкранном плеере, при этом корректно поддерживать back и PiP, если реализован.
7. На планшете/широком окне использовать NavigationRail вместо растянутой нижней панели.

## 6. «Моё» — скриншот 5

Сейчас функционально верно, но визуально почти пусто: три системных пункта. Не нужно декоративно заполнять всё пространство, но можно повысить пользу:
1. Заголовок «Моё» и по возможности профиль/аккаунт (если есть профили).
2. «Мой список» / избранное с горизонтальными мини-постерами, только если есть элементы.
3. «Недавно смотрели» (1–3 компактных превью) с переходом в историю.
4. «Настройки» — отдельный небольшой пункт внизу смысловых секций.
5. Если контент пустой — полезный empty state с действием «Найти фильмы».
6. Не показывать «Скачанное», пока офлайн-функциональность не реализована.

## 7. История — скриншот 6

**Критичные визуальные замечания:** заголовок «История просмо...» обрезается из-за поиска, сортировки и overflow; метаданные `IMDb`, лайки и дизлайки визуально конкурируют с главной задачей экрана.

**Переделать:**
1. AppBar: стрелка Back, короткий заголовок «История», одно меню при необходимости.
2. Показать последнюю просмотренную серию/фильм и прогресс, оставшееся время, дату последнего просмотра.
3. Использовать компактную 16:9 строку (или переключатель «Сетка / Список», если действительно есть польза), а не полный постер с рейтингами.
4. Добавить «Продолжить» при нажатии и контекстное «Удалить из истории».
5. Не смешивать истории просмотра и прогресс: удаление записи истории не должно случайно уничтожать resume state.
6. Проверить сортировку по последнему просмотру, объединение дублей по каноническому playableId / content ID и единообразие карточек.

## 8. Поиск — скриншот 7

**Текущие проблемы:** «Поиск на сайте» вместо «Поиск»; тесные TextField + button; видимая техническая справка о базе/ссылках; длинные описания в поисковой выдаче; постоянно занимающая место кнопка «Показать ещё».

**Переделать:**
1. Заголовок «Поиск», поле на всю ширину, иконка лупы и очистки, placeholder «Фильм или сериал».
2. Использовать `KeyboardActions(onSearch=...)`; кнопку «Искать» можно убрать или оставить внутри поля как компактную trailing action, если нужно.
3. Техническое описание перенести в debug-only диагностику. Пользователь должен знать только область поиска, если она реально ограничена: «Поиск по онлайн-каталогу» (без архитектурных подробностей).
4. Выдача: постер 2:3 размером ~64–72 dp по ширине, название максимум 2 строки, год и тип, описание максимум 2 строки.
5. Каждую карточку результата сделать полностью кликабельной, без лишних элементов внутри.
6. Добавить empty state, loading, error + retry; пагинация inline или плавное подгружание при прокрутке.
7. При запросах к удалённому сайту — либо explicit submit, либо debounce 400–600 мс, `distinctUntilChanged`, `flatMapLatest` / отмена предыдущего запроса, чтобы не спамить источник.
8. Обрабатывать IME insets: результаты и поле не перекрываются клавиатурой, запрос и результаты остаются при возврате со страницы деталей.

## 9. Размеры и типографика (настройки прототипа, не обязательные нормы платформы)

| Элемент | Стартовое значение |
|---|---|
| Горизонтальный padding экрана | 16 dp |
| Межсекционный gap | 24–32 dp |
| Расстояние между карточками | 10–12 dp |
| Ряды подборок | `LazyRow` + edge contentPadding 16 dp |
| Каталог | `LazyVerticalGrid`, 2 колонки на компактной ширине |
| Пропорция постера | 2:3 |
| Пропорция «Продолжить» | 16:9 |
| Радиус карточки | 10–12 dp |
| Радиус chips | 16–24 dp |
| Главный заголовок | 22–24 sp |
| Заголовок секции | 18–20 sp |
| Заголовок карточки | 14–16 sp |
| Метаданные | 12–14 sp, с измеренным контрастом |
| Иконки нижней панели | 22–24 dp |
| NavigationBar | начать с стандартного Material 3, затем тонкая кастомизация |

Проверить fontScale 1.0, 1.3, 2.0 и поддерживать TalkBack. Важные тексты не должны полностью исчезать при увеличенном шрифте.

## 10. Рекомендуемые Compose-компоненты

- `MobileTheme` + `MobileDimens` — **расширить существующие**, не создавать новую параллельную систему.
- `MoviePosterCard` — общий для фильмов и сериалов, передавать тип данных.
- `ContinueWatchingCard` — отдельный 16:9 компонент, прогресс, `SxxEyy`, остаток времени.
- `SectionHeader` — заголовок и опциональное «Все».
- `FeaturedContentCard` — компактный Hero.
- `CatalogSortSelector` — сортировка в toolbar.
- `GenreChipsRow` — `LazyRow` c `FilterChip`.
- `CatalogPosterGrid` — `LazyVerticalGrid` с устойчивыми keys.
- `SearchInput` и `SearchResultRow`.
- `HistoryRowCard` — в первую очередь playback state, не рейтинг.
- `MyLibraryScreen` — библиотечные секции и состояния пустых списков.
- `ScreenScaffold` — централизованная обработка TopAppBar, NavigationBar и insets.
- `UiStateView` — loading / error / empty / content.

Не смешивать работу над UI с миграцией на Media3: она требует отдельного цикла тестирования. Не трогать TV Compose Material ради мобильной палитры; общий слой моделей/данных остаётся общим.

## 12. Проверки и регрессии

**Визуальные:**
- Главная с пустым/1/10 элементами продолжения просмотра.
- Каталог с названиями в 1, 2 и 3 строки, без постера, с медленной загрузкой картинки.
- Фильтры: первый/последний жанр, выбранный вне экрана, быстрые переключения.
- Поиск: пустой ввод, 1 результат, 0 результатов, 100 результатов, сетевой сбой, клавиатура открыта/закрыта.
- История: фильм, серия, завершённое видео, незавершённое, отсутствующий прогресс.
- Навигация: три системные кнопки и жесты; статус-бар/cutout; везде доступна последняя карточка.
- Устройства: 320/360/393/412 dp, планшет 600dp+, альбомная ориентация, fontScale 1.0/1.3/2.0.
- TalkBack и целевые области ≥48dp; контраст проверять программно.

**Функциональные:**
- История, сортировка и фильтры сохраняются после деталей и back.
- При быстром выборе фильтров устаревший ответ не перезаписывает актуальный.
- При возврате из плеера «Продолжить» обновляется без дублей.
- Серии сохраняют правильный `playableId`, не смешиваются координаты эпизодов.
- Нельзя смешивать «очистить историю» и «сбросить прогресс», пока это явно не согласовано.

**Надёжность:**
- `assembleDebug`, unit-тесты, Compose UI tests, screenshot regression tests, ручная проверка на физическом устройстве.
- Следить за лишними рекомпозициями, скачками высоты карточек при загрузке изображения, fps при прокрутке сетки.
