# Каталоги фильмов/сериалов: подтверждение и исправление

Обнаружено при S-004, цикл c-19 revision 12; относится также к существующему S-017
(независимое состояние режимов). Новый шаг не добавлялся, S-004/S-017 целиком не закрыты.

## До исправления

На эмуляторе с реальным каталогом в com.arny.mobilecinema.debug:
- selector btnHomeContentSerial checked=true;
- в сетке показаны «Месть Бетти», «Бабочка в клетке», «Объект преступления»;
- read-only SQL для этих названий вернул только type=1 (фильм), а не type=2.

Локальные артефакты: build/manual/scroll-cards/series-before.xml,
series-after.xml, type-check.txt. Сами пользовательские данные в Git не добавляются.

Причина: обе lazy-зависимости CatalogViewModel внутри одного HomeFragment запрашивались
без квалификатора. Разные parametersOf не создают разные ключи ViewModelStore. Поэтому
первый запрошенный экземпляр использовался и для второго режима.

## Изменения

- HomeFragment запрашивает CatalogViewModel с qualifier FILMS/SERIES.
- KoinModules регистрирует две соответствующие qualified definitions с правильным section.
- Default параметризованная definition оставлена: отдельный каталог/TV не менялись.
- При сборке обнаружилась регрессия ранее добавленной opt-in fixture-конфигурации:
  ignoreList secrets-plugin сохраняла исключённые поля при возврате к обычной сборке.
  Перед условным добавлением fixture-исключений список теперь очищается от этих трёх ключей.
  Иначе default BuildConfig не содержал DATA_LINK/DATA_0_LINK/UPDATE_LINK и не компилировался.
