# S-071: эндпоинты отказов в фикстурном сервере

Добавлено в `scripts/perf_fixtures.py` (проверено на стенде, `build/perf/fixtures/endpoints.json`):

| Эндпоинт | Поведение | Проверка |
|---|---|---|
| `/forbidden` | HTTP 403 `fixture forbidden` | 403, тело 357 Б |
| `/redirect` | HTTP 302 → `Location: /test.mp4` | статус-строка `HTTP/1.0 302 Found` (сырой сокет), после перехода — тот же mp4 |
| `/slow?ms=2000` | ответ через N мс (ограничение 10 000) | 200 за 2017 мс |
| `/test.m3u8` | минимальный HLS-манифест (4 с, один сегмент `test-seg0.mp4`) | 200, тело `#EXTM3U…#EXT-X-ENDLIST` |
| `/test-seg0.mp4` | сегмент манифеста (тот же mp4) | 200, 14 113 Б |
| `net --state off/on` | управляемое отключение сети только для эмулятора | off: wifi_on=0, mobile_data_on=0, airplane_mode_on=1; on: 1/1/0 |

Проверка с эмулятора: после `net --state on` `perf_fixtures.py verify` даёт 7/7 PASS
(значит, сервер достижим и после переключений).

Ограничения, которые нужно помнить:
- `net` работает только на `emulator-<n>` (телефон отклоняется);
- `/slow` держит поток сервера (ThreadingHTTPServer, поэтому параллельные запросы не блокируются);
- эндпоинты доступны только на `127.0.0.1:8765`, наружу сервер не слушает;
- `first frame`-проверки на HLS ещё не выполнялись: добавлен только манифест с одним сегментом,
  а плееру для HLS нужен реальный m3u8-совместимый поток (в текущем стенде это mp4).
