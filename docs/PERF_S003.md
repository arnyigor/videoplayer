# S-003 — диагностическое сравнение debug / benchmark

Приёмка c-13, revision 9: в объёме согласованного S-062 (DONE).
Только эмулятор; физическая проверка отложена и **не выполнена**.

## Что сверено в этом ходе

- Сохранённый результат `build/perf/emulator-comparison.json`: 4 запуска,
  `device_kind=emulator`, API31, экран unlocked до и после каждого замера.
- Merged manifests: `com.arny.mobilecinema.perfdebug` — debuggable=true;
  `com.arny.mobilecinema.perfbenchmark` — debuggable=false, profileable shell=true.
- Общие main sources; benchmark наследует release/R8, debug — обычную debug-конфигурацию.
  Изоляция package ID не меняет прикладную логику. Отличия BuildConfig.DEBUG/R8 намеренные.
- Основание ограничения: S-062 и `build/perf/c12-acceptance-decision.md`.

В c-13 замеры не повторялись: выполнена валидация уже полученных данных и их интерпретация.

## Сценарий и результаты

Pixel_5 API31 на компьютере. Пустые каталоги изолированных пакетов.
Один warmup перед каждым измерением, force-stop процесса, прямой запуск MainActivity,
5 секунд ожидания. Порядок debug / benchmark / benchmark / debug (AB/BA).
Splash/проверка адреса сайта не входят в сценарий; это не полный cold start приложения.

| Показатель | debug | benchmark |
|---|---:|---:|
| TotalTime двух запусков, мс | 1914 / 1726 | 458 / 430 |
| Медиана TotalTime, мс | 1820 | 444 |
| Число кадров по запускам | 15 / 13 | 9 / 9 |
| gfxinfo P95 по запускам, мс | 1350 / 1500 | 200 / 150 |

TotalTime — метрика `am start -W`, gfxinfo percentiles — длительности кадров,
не FrameOverrun и не Macrobenchmark FrameTimingMetric. Единицы — миллисекунды.
Не усредняем P95 разных выборок и не выдаём две точки за устойчивое распределение.

## Вывод для дальнейшей диагностики

В этом узком сценарии non-debuggable benchmark запускался быстрее debug. Это подтверждает,
что оценки только по debug нельзя переносить на release. Причина разницы не установлена:
она может включать R8, debug/logging overhead и нагрузку хоста. По этим данным нельзя
объявить Compose причиной лагов или выбирать оптимизацию.

Следующие замеры производительности ориентировать прежде всего на benchmark; debug
использовать для воспроизведений/логов. S-004 расширяет сценарии на реальные экраны и данные;
этот результат не закрывает S-004, S-005 или PERF-02.

Ограничения: два запуска на вариант, мало кадров, пустой каталог, сеть/температура/нагрузка
хоста не зафиксированы как контролируемые. Не проверены scroll, постеры, заполненная БД,
утечки, ANR и frameOverrun. Нет SLA/FPS-вывода, нет доказательства равенства скорости
эмулятора и телефона. Физическая производительность остаётся непроверенной и не препятствует
согласованному продолжению диагностической работы на эмуляторе.
