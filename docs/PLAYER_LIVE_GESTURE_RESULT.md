# F-019 закрыт: двойной тап работает на живом экране (Media3)

## Как проверено

Инструментальный тест `LiveScreenGestureTest.doubleTapOnLivePlayerSeeksForward`:

1. Запускается настоящая `MainActivity`.
2. Экран плеера открывается напрямую через `NavController` с реальным URL фикстуры
   (`http://127.0.0.1:8765/test.mp4`) и объектом `Movie` — каталог и БД не нужны, поэтому
   проблема «instrumentation удаляет приложение вместе с БД» больше не мешает.
3. На экране проверяется, что найден именно `com.github.vkay94.dtpv.DoubleTapPlayerView`
   из Media3-форка и что у него есть `player` (Media3).
4. Касания синтезируются на главном потоке (adb `input tap` не годится: ~610 мс между
   вызовами при окне двойного тапа в сотни мс — `build/perf/c70-live/tap-timing.json`).
5. Позиция до/после двойного тапа в правой половине: **перемотка ≥ 8 с** → PASS.

## Результат прогонов (CPU-эмулятор, SwiftShader)

| Прогон | Итог |
|---|---|
| `LiveScreenGestureTest` | PASS |
| Пакет `presentation.playerview` целиком | **15/15 PASS**, 0 failed (`build/perf/c70-live/all.log`) |
| Юнит-тесты приложения | BUILD SUCCESSFUL (`build/perf/c70-live/unit.log`) |

То есть после миграции на Media3 YouTube-жест (двойной тап → перемотка) работает **в самом
приложении**, а не только на уровне компонента; оверлей и разметка `f_player_view.xml`
подключены как раньше.
