# S-011: ориентация и режим вписывания после миграции на Media3

## Проверка

`PlayerOrientationResizeTest` на CPU-эмуляторе:

1. Экран плеера открывается через `NavController` с реальным URL фикстуры.
2. В портрете: вьюха — `com.github.vkay94.dtpv.DoubleTapPlayerView` (Media3 `PlayerView`),
   `resizeMode = RESIZE_MODE_FIT` (значение приложения по умолчанию «Оригинал»).
3. Поворот в ландшафт: `Configuration.ORIENTATION_LANDSCAPE`, вьюха того же класса, то есть
   после пересоздания экрана Media3-плеер восстановился.
4. Воспроизведение при повороте не встало: позиция выросла за 2.5 с.
5. Обратный поворот в портрет: `ORIENTATION_PORTRAIT`.

## Остаток по S-011 и почему он не закрывается этим циклом

- **Субтитры и аудиодорожки** — проверить нечем: единственный фикстурный поток содержит
  только видео-дорожку (`ffprobe`: `0,h264,video`), субтитров и второй аудиодорожки нет.
  Нужен фикстурный файл с несколькими дорожками (см. отдельную находку), иначе проверка
  будет фиктивной.
- **Ads** — в приложении нет интеграции IMA: ни одного обращения к `ImaAdsLoader` /
  `com.google.ads.interactivemedia` в коде нет, поэтому при миграции неиспользуемая
  зависимость `exoplayer-extension-ima` была убрана. Проверять нечего, пока реклама не
  появится как функциональность.
- **Анимация оверлея «+10 с»** — визуальная часть; тест подтверждает саму перемотку, но не
  картинку.
- **TV-экран** — мигрирован механически, на TV-устройстве/эмуляторе не запускался.
