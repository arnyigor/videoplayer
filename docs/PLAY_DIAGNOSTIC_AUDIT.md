# S-008: начальная сверка цепочки запуска

Статическая проверка после указания оператора продолжать без физического замера.
План revision18 не изменён. S-065/S-007 не закрыты.

Подтверждено исходниками:
- DetailsFragment.kt:306–307 — btnPlay.setOnClickListener вызывает playMovie напрямую. Промежуточный ViewModel intent для этого входа отсутствует по архитектуре; требовать его как реально существующий этап неправильно.
- :1122 — PlayStartResolver получает currentMovie, позиции сезона/эпизода и выбранный индекс источника. Отказ показывает toast и обновляет enabled.
- :1160–1193 — Wi-Fi ведёт к навигации, mobile/offline требуют подтверждения диалога. Это штатные промежуточные остановки, не доказанный дефект.
- :1203 — перед навигацией resolver вызывается повторно; Ready.source.url передаётся как path в nav_player_view. Для сериала передаются seasonIndex/episodeIndex. Исключение навигации показывает toast.
- PlayerViewFragment.kt:219–242 — onPlayerError показывает ошибку и вызывает retryOpenCinema; onPlaybackStateChanged передаёт состояние updateState.
- В прочитанном listener нет onRenderedFirstFrame. Само наличие READY не доказывает показ первого кадра.

Пока НЕ проверено: один фактический клик от pointer до первого кадра, перехват overlay/enabled, соответствие фактического URI, создание MediaItem и prepare, поведение повторных кликов и stale collectors. Статический аудит не закрывает S-008 и не устанавливает причину исходного отказа.
