## Чего не хватает для полного закрытия S-010

1. **Instrumentation-проверки плеера**: READY / first frame / error через fake URL. Сейчас
   это подтверждено руками (`PLAY_CHAIN.md`), но не тестом.
2. **Navigation**: Back из плеера возвращает в детали с сохранённым состоянием — теста нет.
3. **Матрица отказов**: 403, 404, redirect, HLS manifest, медленный DNS, offline. Для неё нет
   стенда: `scripts/perf_fixtures.py` отдаёт 200 на постеры, 404 на `missing`, байт-диапазоны
   на `test.mp4`, но не умеет 403, redirect-цепочку, задержку ответа и не имеет HLS-манифеста.
   Без этих эндпоинтов кейсы «URL 403/404, redirect, HLS manifest, медленный DNS» не воспроизвести
   честно — эмуляция тоста без реального отказа ничего не доказывает.

Поэтому S-010 остаётся незавершённым: часть критериев упирается в отсутствие стенда отказов,
а не в отсутствие кода.

## Приёмка из плана (частично)

«Нажать СМОТРЕТЬ → виден loader → открывается плеер и начинается воспроизведение либо понятное
сообщение с Retry/Change source». Успешная ветка подтверждена живым прогоном (`PLAY_CHAIN.md`,
`chain2-logcat.txt`). Ветка «понятное сообщение с Retry/Change source» на устройстве не
проверялась: тосты есть, но кнопок Retry/Change source в диалоге ошибки запуска нет — сейчас
после ошибки плеера вызывается `retryOpenCinema`, а на отказ резолвера показывается только тост.
Это расхождение с формулировкой приёмки стоит решать в S-011 (PLAY-02), а не здесь.
