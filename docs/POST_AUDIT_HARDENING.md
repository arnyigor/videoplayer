# Пост-аудитные доработки

Срез после аудита мобильной версии и Android TV. Субтитры по решению продукта убраны, а не починены.
TLS не менялся. Удаление карточек по 404 не реализовывалось.

## Что изменено

### Субтитры убраны

- Мобильный плеер: удалены `SubtitleView`, скрытая кнопка `ivSubtitle`, список субтитров и связанный код; текстовые дорожки отключены в селекторе.
- TV-плеер: удалена кнопка `btnSubtitles`, диалог субтитров, `subtitleChoices`; текстовые дорожки отключены.
- `TvTrackChoices.kt`: помощник сужен до аудио (`tvAudioParameters`), добавлены различимые подписи (`en (1)`, `en (2)`).

### Мобильный плеер

- `PlayerExtentions.kt`: перечисление языков, качеств и субтитров больше не меняет параметры выбора дорожек. Ранее каждый вызов собирал `TrackSelectionParameters` с `clearOverridesOfType` и присваивал его оверрайду.
- `PlayerViewFragment.kt`: выбор качества очищает только видео-оверрайды, выбор языка — только аудио. Убран `setTunnelingEnabled(true)` из пути выбора языка.
- Автовыбор максимального качества выполняется один раз на медиаэлемент, а не при каждом `onTracksChanged`.
- Потеря audio focus теперь ставит паузу независимо от PiP; lifecycle-пауза по-прежнему не срабатывает в PiP.

### Входящие ссылки

- `SplashViewModel`: URL передаётся Activity через extra, а не через `SharedFlow` без replay, который терялся до появления подписчика.
- `MainActivity`: добавлены `onNewIntent` и обработка `KEY_SHARED_URL` — загрузка карточки, ожидание RESUMED, переход в детали по `id`, сообщение об ошибке, снятие extra только после обработки.

### Разрешения и каталог

- `HomeFragment`: каталог загружается сразу, без цепочки «уведомления → WRITE_EXTERNAL_STORAGE → загрузка».
- `CatalogViewModel`: жанр, сортировка, позиция сетки и фокус сохраняются в `SavedStateHandle`; смена фильтра сбрасывает устаревшую позицию; при восстановлении запрашивается достаточно данных, чтобы вернуться к сохранённой позиции.
- `retry()` различает начальную ошибку и ошибку следующей страницы: вторая догружает с того же offset.
- Мобильный и TV каталог показывают footer с Retry при ошибке уже загруженного списка.

### Скачивание

- `MovieDownloadService`: сообщение «сохранено» и broadcast отправляются только при успешном копировании; при ошибке показывается отдельное сообщение, а скачанный оригинал не удаляется. Временные файлы чистятся только после успешного сохранения.
- Сервис скачивания переведён на `dataSync` (манифест и `startForeground`), добавлен `onDestroy` с отменой job и освобождением listener. Задача больше не подменяет родительский Job через `launch(coroutineContext)`.

### TV

- `TvSessionPlayer`: команды системной MediaSession идут через ту же логику, что и медиакнопки пульта — Pause/Stop отменяют отсчёт следующей серии, Play/Next запускают ожидающую серию.
- Диалог качества сохраняется и закрывается в `onDestroyView` вместе с диалогом дорожек.
- Корневые разделы меню получили отдельные destinations (`tvSeriesCatalogFragment`, `tvFavoritesLibraryFragment`) и переключаются с `saveState`/`restoreState`: состояние раздела переживает переход в другой раздел.
- `CatalogUpdateTracker`: терминальное состояние и факт незавершённой операции сохраняются в prefs; при следующем запуске незавершённая операция помечается `INTERRUPTED`, а не выдаётся за текущую.
- URL источников больше не пишутся в логи целиком.

### Lint и CI

- Lint: 343 ошибки → **0**. `UnsafeOptInUsageError` (339) закрыт файловыми `@file:androidx.annotation.OptIn(UnstableApi::class)` в `PlayerSource.kt`, `PlayerViewFragment.kt`, `PlayerExtentions.kt`, `MovieDownloadService.kt`, `VideoCache.kt`, `ApiUtils.kt`; `UseAppTint` исправлен заменой `android:tint` на `app:tint`.
- Три TV-ошибки (`MissingLeanbackLauncher`, `ImpliedTouchscreenHardware`, `MissingLeanbackSupport`) указывали на `src/debug/AndroidManifest.xml`, хотя merged-манифест содержит `LEANBACK_LAUNCHER` и оба `uses-feature` из `src/main`. Подавлены только эти три проверки в debug-манифесте с комментарием; декларации в main не менялись.
- CI: lint больше не `continue-on-error`, добавлена выгрузка lint-отчёта; в release-workflow unit-тесты обязательны перед публикацией.

## Постеры (обязательное требование)

- Один загрузчик для всех поверхностей: `presentation/utils/PosterRequests.kt` (`ImageView.loadPoster`) + `PosterImage`
  для Compose. Мобильные карточки, детали, история и TV-карточки/баннер/эпизоды переведены на него; отдельные
  `Glide.with(...)` вызовы и `AsyncImage` в этих местах убраны.
- Разбор пути централизован: `data/utils/PosterUrls.kt` (`posterUrlCandidates`) — абсолютные/протокол-относительные
  и относительные пути, `&amp;` и пробелы, отказ от `file:`/`content:`/`data:`; повтор только по текущему зеркалу
  сайта, для внешних CDN — один переход `http→https`.
- `Accept` для изображений приведён к обычному браузерному (AVIF убран: сервер отдавал формат, который Glide не декодирует).
- Debug-вариант получил собственный `network_security_config` с cleartext только для loopback (локальные фикстуры);
  в release-APK этих доменов нет (проверено по `resources.arsc`).

Проверено: 8 инструментальных тестов на телефонном и 8 на TV-эмуляторе (загрузка, кэш без сети, подмена при смене
карточки, очистка, fallback, отказ/404 без цикла, реальные пиксели на экране для мобильных и TV-компонентов),
плюс живой тест: реальный постер `mm.anwap.media` декодируется через пайплайн приложения загрузкой настоящего
каталога (47 871 запись) в release-сборке.

## Не проверено

- Мобильные сценарии проверены на эмуляторе Pixel_5 (API 31), а не на физическом телефоне. Аппаратные особенности (реальный вызов, Bluetooth, кнопка гарнитуры) не покрыты.
- Тёплая доставка ссылки (`onNewIntent`) на мобиле не покрыта автотестом: второй запуск `singleInstance`-Activity из теста не удаётся однозначно приписать конкретному экземпляру. Код реализован, TV-путь проверен вручную ранее.
- Ошибка копирования в «Загрузки» (C-02) не воспроизводилась: путь ошибки реализован, но не подтверждён отказом MediaStore.
- TV: физический пульт/CEC, голос, длительное удержание, восстановление после уничтожения процесса ОС.
- Миграции старых баз v1/v2 — без исторических образцов не проверяются; граница поддержки остаётся неопределённой.
- 334 lint-предупреждения не разбирались; они не блокируют сборку.
- TV-поиск: чипы получили собственный фон с внутренним инсетом, отступы, однострочную подпись и явный префикс
  «Сортировка: …». Кажущаяся «квадратность» ряда фильтров — не дефект: Leanback приглушает ряды без фокуса
  (проверено диагностической заливкой: все чипы используют один и тот же фон).
- Скриншоты с реальными данными: `build/subtitles/shots/` (телефон: home, films, series, details, player, settings,
  history, favorites, search; TV: home, films, series, details, settings, search, history, favorites).
