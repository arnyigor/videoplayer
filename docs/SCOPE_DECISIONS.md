# Решения по объёму: физическое подтверждение PERF-02

## 2026-10-30 — оператор: «давай пока без замера, работай дальше»

Прямое указание оператора: физический замер PERF-02 (шаг **S-065**, происхождение —
находка **F-008**) сейчас не выполняется. Эмулятор занят другим агентом, телефон
заблокирован и используется по усмотрению владельца; ранее тестирование на нём
откладывалось дважды («плавность на телефоне проверю позже»).

### Что это меняет

- **S-065 остаётся невыполненным.** Данных с физического устройства нет; эмуляторными
  числами они не подменяются (см. `docs/PERF_REPORT.md` §5).
- Пункт приёмки **S-007** «фиксируемая разница на физическом устройстве» остаётся открытым
  по решению оператора, а не по технической причине.
- Остальные результаты PERF-02 действительны в эмуляторном объёме:
  - аудит кодовой базы по пунктам PERF-02 (см. `docs/PERF_REPORT.md` §1);
  - правка `collectAsState()` → `collectAsStateWithLifecycle()` в мобильных Compose-экранах;
  - замеры до/после в идентичных условиях: медиана P95 21 → 21 мс, ANR нет
    (`build/perf/c29/after-lifecycle.json`);
  - atrace-разбор главного потока: 918 кадров, медиана 5.23 мс, P95 9.81 мс,
    **0 слайсов ≥ 50 мс**, хвост — в `DrawFrame`/`eglSwapBuffers` на RenderThread
    (`build/perf/c30/atrace-summary.json`, трасса `build/perf/c30/c30.trace`);
  - 191 юнит-тест зелёный.

### Условие возобновления (когда владелец даст слот или пришлёт цифры)

Протокол — `docs/PERF_MEASUREMENT.md`. Минимальный запуск на физическом устройстве:

```sh
adb -s <phone-serial> install -r app/build/outputs/apk/benchmark/*benchmark.apk
python scripts/perf_metrics.py --serial <phone-serial> --seconds 15 \
    --out build/perf/physical/metrics-$(date +%H%M).json     # повторить ≥5 раз
```

Требуется: ≥5 прогонов одинакового сценария на physical-устройстве и non-debuggable
benchmark-сборке, фиксация условий (модель, API, экран, батарея, сети), сравнение медиан
P50/P95/P99 с разбросом, проверка отсутствия ANR и добавление раздела «physical» в
`docs/PERF_REPORT.md`. Только после этого S-065 и остаточный пункт S-007 закрываются.

До этого момента никакие выводы о плавности на реальном устройстве не делаются.

## 2026-11-01 — оператор: «субтитры пока не работают, отложи их»

Субтитры вынесены в отдельный шаг **S-075** (P2) и помещены в конец списка шагов вместе с
незавершённым S-011 (Media3, TV-плеер). Причина: список субтитров теперь строится и кнопка
появляется, но включение дорожки через `TrackSelectionOverride` не активирует её — ни выбор
из меню, ни отрисовка текста не подтверждены, а подбирать «наугад» неверно.

Следующий активный шаг — **S-012** (единый экран поиска). S-011 и S-075 не объявлены
выполненными.

## Решение оператора: TalkBack — на финальную ручную приёмку

Оператор: «либо убери этот пункт либо перемести в конец. будет ручная приёмка, я буду проверять».

- Проверку TalkBack (**S-078**) откладываем до финальной ручной приёмки оператором;
  выполненной её не считаем. Установка TalkBack на AVD (**S-079**) больше не нужна
  как предварительный блокер текущей работы.
- Остаточный критерий TalkBack в **S-021** также относится к этой ручной приёмке,
  а не к автоматизированному подтверждению сейчас.
- Контроллеру требуется перенести S-078 в конец плана и снять S-079 как обязательную
  предпосылку. Контроллерный файл напрямую не изменён.
- Далее: оставшиеся проверки **S-021** (edge-to-edge, иконки/selected, остальные
  View-диалоги, ширина 393dp), затем **S-022** — обслуживание каталога.
