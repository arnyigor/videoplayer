# S-014: релевантность и дедупликация поиска

## Что было не так

`SearchRelevance` различал только «точное / начинается / слово / подстрока», причём
**основное и оригинальное название оценивались одинаково** (`max`): для запроса `the matrix`
карточка «Матрица / The Matrix» получала ту же оценку, что и точное совпадение названия.
Нормализации не было: `Ёлка` и `елка`, `The   Matrix` и `the matrix` сравнивались по-разному.

## Что сделано

`domain/search/SearchRelevance.kt`:

1. **Нормализация** (`normalize`): Unicode NFC → нижний регистр (`Locale.ROOT`) → `ё`→`е` →
   сжатие пробелов → trim. Одна функция используется и для запроса, и для названий.
2. **Строгий порядок оценок:** `EXACT` (100, основное название) > `EXACT_ORIGINAL` (90) >
   `STARTS_WITH` (80) > `WORD_STARTS_WITH` (60) > `CONTAINS` (40) > `FUZZY` (20) > `NO_MATCH`.
   Точное совпадение оригинального названия теперь слабее точного совпадения основного.
3. **Fuzzy** — расстояние Левенштейна с допуском 1 (для запросов ≥4 символов) и 2 (≥7),
   только последним приоритетом. Для коротких запросов (≤3) fuzzy отключён, чтобы выдача не
   заполнялась случайными подсказками.
4. Рейтинг IMDb в оценку не входит (проверено тестом).

## Тесты

`SearchRelevanceTest` — 9 тестов, все PASS: точное/префикс/слово/подстрока; латинский запрос
через оригинальное название; `matrix` vs `the matrix` (EXACT против EXACT_ORIGINAL); регистр,
лишние пробелы, `ё`; опечатка → FUZZY ниже CONTAINS; короткий запрос не угадывается; рейтинг
не влияет; стабильность порядка при равных оценках; пустой запрос.

Полный прогон юнит-тестов: **225 тестов, 0 падений** (`build/perf/c84-all.log`).

## Что осталось по S-014

- Дедупликация (п.5) уже реализована в `SearchMerge` и покрыта `SearchMergeTest` (12 тестов),
  отдельно этот шаг её не менял.
- Отмена предыдущих запросов (п.6): в `SiteSearchViewModel` новый поиск отменяет прошлый Job и
  сверяет запрос перед применением результата — это код, покрытый косвенно; генерационного
  токена (request generation) нет, только сравнение строки запроса.
- Серверная пагинация (п.7): при смене запроса/фильтров `filmsPage` сбрасывается в 0, но
  отдельного теста на смешивание страниц нет.

## Дополнение (c-85): закрыты остатки п.6 и п.7

1. **Поколение запроса (request generation).** В `SiteSearchViewModel` добавлен счётчик
   `requestGeneration`: каждый поиск получает номер, и ответ применяется только если номер
   совпадает с текущим. Раньше защита была только сравнением строки запроса — при смене scope
   или фильтров строка та же, поэтому устаревший ответ мог попасть в новую выдачу.
   `loadMore()` тоже фиксирует поколение.
2. **Тесты на это:**
   - `stale local result is dropped when scope changes with same query` — каталог отвечает
     с опозданием, пока пользователь переключился на «только сайт»; поздняя локальная выдача
     **не попадает** в список;
   - `new search resets paging so pages are not mixed` — новый запрос обнуляет `filmsPage`
     до ответа сайта, строки прошлого запроса не остаются;
   - итого `SiteSearchViewModelTest` 5/5 PASS, полный прогон — **227 тестов, 0 падений**
     (`build/perf/c85-all.log`).

Осталось непроверенным по S-014: поведение fuzzy на реальных данных сайта (проверено только
юнит-тестами на синтетических названиях).

## Дополнение (c-86): fuzzy на реальных данных

В ответ фикстурного сайта добавлен тайтл **«Matrx Legacy»** (содержит опечаточный запрос
буквально) и разрешён запрос `matrx`; это даёт на одном экране три разных уровня оценки.

Проверка на CPU-эмуляторе (запрос `matrx`, режим «Везде»), порядок в списке сверху вниз
(`build/perf/c86/typo.xml`, скриншот `build/perf/c86/fuzzy-order.png`):

| Позиция | Тайтл | Почему |
|---|---|---|
| 1 | **Matrx Legacy** | `CONTAINS` (40): запрос входит в название буквально |
| 2 | Матрица (orig. The Matrix) | `FUZZY` (20): опечатка в слове «matrix» |
| 3 | Матрица: Воскрешение | `FUZZY` (20), порядок сохранён по индексу ответа |

То есть fuzzy работает на живых данных и **не поднимается выше** точного вхождения, как требует
план. Локальных результатов в этом запросе нет — SQL не находит «matrx», это ожидаемо.

Остаток по S-014: ничего не осталось; `SearchRelevanceTest` 9/9, `SiteSearchViewModelTest` 5/5,
`SearchMergeTest` 12/12, полный прогон 227 тестов без падений.
