# S-012: единый экран поиска — что сделано

## Сверка (revision 34)

Экран уже почти соответствовал плану: `sitesearch/SiteSearchFragment` + `SearchFiltersSheet`,
лупа главной ведёт в него (`HomeFragment.kt:1057-1061`), есть одно поле, IME-search, выбор
источника «Везде / В каталоге / На сайте», локальная выдача показывается до сайта, шит фильтров
с черновиком и кнопкой **Apply** (`btnFiltersApply` → `setFragmentResult`).

## Изменения этого цикла

1. **`scope=CATALOG`.** В граф добавлен nullable-аргумент `scope` у `nav_site_search`;
   при `scope=CATALOG` экран сразу открывается по локальному каталогу (`SearchSource.LOCAL`).
   Раньше аргумента не было — открыть поиск с предвыбранным каталогом было нельзя.
2. **Разные сообщения об ошибках источников.** Было одно «Не удалось выполнить поиск на сайте»
   на любой отказ. Добавлена строка `search_local_error` («Не удалось выполнить поиск
   в каталоге»), и `render()` выбирает текст по тому, какой источник упал: только каталог →
   локальное сообщение, сайт → сетевое, оба → общая ошибка.

## Проверено

- `:app:compileDebugKotlin` — BUILD SUCCESSFUL; `:app:testDebugUnitTest` — зелёные.
- Инструментальный `SearchQueryIntegrationTest` на CPU-эмуляторе:
  - **PASS** `queryAndSourceSurviveBackFromDetails` (новый): запрос «матрица» и выбранный
    локальный источник сохраняются после ухода на главную и повторного входа на поиск —
    то есть критерий «возврат в ту же вкладку/запрос» для этого пути выполняется;
  - **SKIP** `rapidUnicodeQuerySurvivesSourceSwitches`: проверка устаревших ответов требует
    непустого локального каталога, а instrumentation-прогон удаляет данные приложения.
    Тест переведён на `Assume`, чтобы не падать на пустой базе; это не «прошло», это
    «не проверено в этих условиях».

## Что осталось по S-012

   «Каталог недоступен — показаны результаты сайта». Раньше был только общий прогресс-бар.

## `extendedsearch` — исправлять не нужно

Старый экран **не открывается пользователем**: действие `action_nav_home_to_nav_extended_search`
есть в графе, но в коде на него нет ни одного перехода; `MainActivity` лишь скрывает для него
нижнюю навигацию, а `HomeFragment` читает его результат, если он когда-то придёт. То есть второго
пути поиска в UI нет, и удаление мёртвого кода — отдельная чистка, не правка поведения.

## c-80: остаток по S-012

- **Clear + IME Search** — уже было: `app:endIconMode="clear_text"` в `tilSiteSearch`,
  `android:imeOptions="actionSearch"`.
- **Empty-текст по источнику** (добавлено сейчас): раньше при поиске только по каталогу писалось
  «Ничего не найдено на сайте». Теперь «Ничего не найдено в каталоге» / «…на сайте» /
  «Ничего не найдено» для «Везде». Сборка и юнит-тесты зелёные (`build/perf/c80-build.log`).
- **Позиция списка при Back** — отдельно не проверена: instrumentation-прогон удаляет данные,
  поэтому каталог пуст и прокручивать нечего. По коду возврат из деталей идёт в тот же экземпляр
  фрагмента в back stack, а `RecyclerView` сохраняет своё состояние в состоянии view; это
  рассуждение, а не проверка — в отчёте оставлено как непроверенное.
