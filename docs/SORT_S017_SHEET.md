# S-017: общий лист сортировки каталога + разграничение с лентой «Все»

## Что сделано

1. **Общий `CatalogSortSheet`** (Compose `ModalBottomSheet`) в `MobileCatalogScreen.kt`.
   Раньше сортировка каталога открывала `DropdownMenu` внутри кнопки — это была единственная
   реализация, и любое второе место потребовало бы копии. Теперь лист один, вызывается из
   `CatalogSortSelector`; заголовок «Сортировка каталога», текущий режим отмечен галочкой.
2. **Проверено на устройстве** (CPU-эмулятор, perfdebug):
   - кнопка сортировки в «Фильмах» открывает лист (`build/perf/c89/sheet.xml`,
     `build/perf/c89/sort-sheet.png`);
   - выбор «По рейтингу» применяется и отражается в `contentDescription`
     «Сортировка: По рейтингу» (`build/perf/c89/after-rating.xml`, `after-rating.png`).
3. **Пункт overflow переименован, а не удалён.** Разбор кода показал: `action_order_settings`
   открывает не сортировку каталога, а порядок ленты «Все» (`showCustomOrderDialog`,
   `HomeFragment.kt:1039`). Удаление лишило бы пользователя настройки единственной ленты.
   Поэтому пункт назван «Порядок ленты «Все»» — теперь его не спутать с сортировкой каталога.
   Это осознанное отступление от п.7 плана, а не пропуск.

## Что уже было (проверено кодом, не переделывал)

- **Сортировка в SQL, не на UI:** `PagingSourceHelper` собирает `ORDER BY` по
  `CatalogSort.order` (`AppConstants.Order.YEAR_DESC / RATINGS / TITLE`), пагинация через
  PagingSource; на UI-потоке список не сортируется.
- **Смена сортировки сбрасывает только каталог:** `CatalogViewModel.selectSort` →
  `CatalogPaging.withFilter` очищает `items`, `endReached`, paging; лента «Все» и прогресс
  пользователя не затрагиваются.
- **Отдельное хранение по режимам:** на главной два квалифицированных `CatalogViewModel`
  (`named(CatalogSection.FILMS)` и `named(CatalogSection.SERIES)`), то есть сортировка и жанр
  у фильмов и сериалов не пересекаются.
- **Кнопка только у «Фильмы/Сериалы»:** встроенный каталог показывается для этих вкладок
  (`HomeFragment.kt:899`, `showTitle = false`); во «Все» лента показывает подборки, кнопки
  сортировки каталога там нет.

## Не проверено

- `ComposeTestRule` на selection/semantics нового листа (приёмка плана) — тест не писал.
- Кнопка с «подписью выбранного режима» на самой кнопке: подпись убрана по прямой просьбе
  оператора (только иконка), режим виден в `contentDescription` и галочкой в листе.
  Это конфликт плана и указания владельца, решён в пользу владельца.
- Сохранение scroll/selection после возврата из деталей для каталога отдельно не снималось
  в этом цикле (для поиска проверено в c-81).

## Что осталось непроверенным (честно)

- **Сохранение сортировки после Back из деталей** и **прокрутка каталога**: в этом цикле
  проверить не удалось — на фикстурной базе каталог показывает только три карточки
  (одна строка), прокручивать нечего, а после нескольких переключений вкладок экран ушёл на
  «ВСЕ». Это ограничение состояния стенда, а не доказанное отсутствие сохранения: сортировка
  хранится в `CatalogViewModel` (два квалифицированных экземпляра на главной), а ViewModel
  переживает переход в детали.
- Три режима на **сериалах** отдельно не прогонялись: компонент общий, но проверка была на
  «Фильмах».

## c-91: почему «сохранение сортировки после Back» и прокрутку проверить не удалось

На фикстурной базе (500 фильмов, `type=1`) каталог «Фильмы» показывает **три карточки** и не
прокручивается: свайпы внутри сетки (y 600–1900) не меняют ни первый видимый элемент, ни
координаты. Дамп при этом содержит **два** прокручиваемых контейнера:

```
SCROLLABLE: android.view.View                        [0,618][1080,1465]   ← Compose-сетка
SCROLLABLE: android.widget.GridView ...id/rcVideoList [0,442][1080,2054]  ← legacy GridView
SCROLLABLE: androidx.recyclerview.widget.RecyclerView ...id/rvRecent
```

То есть на экране одновременно присутствуют Compose-каталог и старый legacy-список, и
причина непрокручиваемости не локализована: либо перехват жеста соседним контейнером, либо
в состояние каталога реально попадает только три элемента.

SQL при этом отдаёт по первому запросу больше строк:

```
199|Fixture 00199|1|2024
399|Fixture 00399|1|2024
599|Fixture 00599|1|2024
799|Fixture 00799|1|2024
999|Fixture 00999|1|2024
```

Значит данные есть, а на экран попадает три — это отдельный дефект, зарегистрированный как
F-030. Проверять «сохранение сортировки после Back» и «прокрутку» до его разбора бессмысленно:
прокручивать нечего.
