# S-021 — edge-to-edge, c-111 (revision 60)

План и результаты c-110 перечитаны. Контроллерный план не изменялся; TalkBack остаётся на финальной ручной приёмке S-078.

## Изменено

- MainActivity рисует окно edge-to-edge с прозрачными системными панелями и светлыми системными значками на тёмном фоне.
- На обычных экранах Activity применяет объединение systemBars, displayCutout и IME как padding корневой View. Отступы не суммируются: берётся максимум для каждой стороны. Insets потребляются, чтобы BottomNavigationView не добавлял нижний отступ повторно.
- Для nav_player_view padding Activity равен нулю, исходные insets передаются плееру: он сохраняет собственные отступы контролов и immersive-режим.
- При смене destination запрашивается повторное применение insets. Выход из плеера больше не включает decorFitsSystemWindows=true; для API <30 также восстанавливаются layout-флаги edge-to-edge после SYSTEM_UI_FLAG_VISIBLE.

## Проверено на emulator-5554, Android 11

Добавлен EdgeToEdgeInsetsTest. Он реально проверяет:

1. Корневая View начинается у верхней границы экрана (y=0), её padding точно равен safe insets.
2. Те же равенства в landscape и после возврата в portrait.
3. Клавиатура действительно видима; padding учитывает IME, нижняя навигация не дублирует нижний inset.
4. После перехода в плеер padding Activity по всем сторонам равен нулю.
5. После popBackStack из плеера снова выполнены равенства safe insets, root y=0.

Регрессионный прогон: **3 теста, 0 ошибок, 0 пропусков, Gradle exit=0**:
- EdgeToEdgeInsetsTest;
- PlayerOrientationResizeTest (воспроизведение продолжилось после поворота);
- PlayerPipTest (воспроизведение продолжилось в PiP).

Лог: `build/perf/c111/regression.log`; XML результата скопирован в ту же папку. Сервер фикстуры отвечал 200 на /test.mp4, adb reverse 8765 настроен только на эмуляторе.

## Остаток и риски

- Runtime-проверка только Android 11 с трёхкнопочной системной навигацией. API <30, Android 15+, gesture navigation и разные вырезы отдельно не проверены.
- Тест не покрывает все экраны и все зоны нажатия. На обычных экранах insets теперь принадлежат Activity; экран, которому нужны исходные insets, требует отдельного рассмотрения.
- Диалоги порядка, обновления и удаления закладки на подходящих данных ещё требуют проверки (остаток S-021/F-041).

S-021 не закрыт. Новых отдельных дефектов или блокеров среды не обнаружено.
