# S-021: тёмный диалог ошибки плеера — найдено и исправлено

## Как воспроизвёл

В фикстурной базе у видимой карточки (`dbId=199`) поставил `hdUrls = http://127.0.0.1:8765/forbidden`,
открыл детали → «Смотреть». Плеер получает 403 и показывает View-диалог с ошибкой.

## Что было не так (три итерации, все по скриншотам)

1. **Светлая плашка на тёмном экране** — в теме не были заданы `colorSurface` /
   `android:colorBackground`, Material-диалоги брали светлые значения DayNight
   (`error-dialog2.png` → после первой правки фон стал тёмным).
2. **Тёмный текст на тёмном фоне** — после затемнения surface сообщение стало нечитаемым.
   Добавлены `android:textColorPrimary` / `android:textColor` в `MyDialogStyle`
   (`error-dialog3.png` → текст читается).
3. **Кнопки «ПОВТОРИТЬ / ОТМЕНА / ВЫБРАТЬ ИСТОЧНИК» оставались тёмными**: в Material
   TextButton текст берётся из `colorPrimary`, а он в тёмной теме почти чёрный.
   В `MyDialogStyle` `colorPrimary` теперь `@color/colorAccent`
   (`error-dialog4.png` → кнопки акцентные, читаются).

Итог: диалог ошибки полностью читаем — сообщение белым, кнопки акцентным цветом
(`build/perf/c106/error-dialog4.png`).

## Побочный эффект, который надо помнить

Правки темы (`colorSurface`, `colorPrimary` в диалоге) касаются **всех** View-диалогов
приложения, а не только ошибки плеера: они станут тёмными с акцентными кнопками. Это
соответствует тёмному UI, но визуально остальные диалоги в этом цикле не перепроверялись.

Фикстурная база (изолированный пакет `perfdebug`) осталась с изменёнными ссылками у `dbId 199/399`
— на продовое приложение это не влияет.
