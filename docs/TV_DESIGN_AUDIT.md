# Аудит дизайна Android TV — Anwap Movies

Дата: 2026-10-20. Объект: `app/src/main/java/com/arny/mobilecinema/presentation/tv/**`,
`app/src/main/res/layout/f_tv_player.xml`, `res/navigation/tv_nav_graph.xml`, `res/values/themes.xml`,
`res/values/colors.xml`, `res/values/styles.xml`, `res/drawable/tv_*`, `AndroidManifest.xml`.

Документ состоит из аудита (разделы 1–9) и плана улучшений (разделы 10–12).
Каждая находка имеет идентификатор `F-xx`, ссылку на код и пометку источника факта:

- **[код]** — проверено чтением исходников проекта;
- **[ресурс]** — проверено по ресурсам библиотеки (Leanback 1.1.0-beta01, exoplayer-ui 2.19.1,
  `androidx.tv:tv-material 1.1.0`), распакованным из Gradle-кэша;
- **[экран]** — проверено на живом эмуляторе (см. раздел 12);
- **[док]** — требование из документации Google/Amazon (ссылки в разделе 2).

## 1. Главные выводы (TL;DR)

1. Каркас TV-части сделан на Leanback (`BrowseSupportFragment`, `DetailsSupportFragment`,
   `SearchSupportFragment`), но **дизайн-системы как таковой нет**: размеры, отступы, цвета и состояния
   фокуса заданы магическими числами внутри презентеров, без `dimen`/`TextAppearance`/`color`-токенов.
2. **Три системные ошибки тиражируются по всему TV-UI**:
   - размеры в `setPadding(...)` и `setMainImageDimensions(...)` переданы **в пикселях**, а не в dp
     (на 1080p/320dpi всё вдвое мельче задуманного);
   - состояние «выбрано» и состояние «фокус» у чипов визуально почти не различаются
     (`bg_sort_category_selector`), у карточек сезонов/источников состояние «выбрано» вообще мертво
     (`val selected = false`);
   - у главной включены Leanback-«headers» с **пустыми** заголовками: слева постоянно висит колонка
     270dp, два верхних ряда чипов дают пустые слоты в списке заголовков.
3. **Плеер визуально беднее, чем позволяет платформа**: нет индикатора буферизации (`showLoading()` — пустой
   метод), нет скраббинга прогресс-баром (он `focusable="false"`), шаг перемотки 5 с без обратной связи,
   нет оверлея «следующая серия», ошибка выводится сырым текстом исключения без действия «Повторить».
4. **Элементы оверлея плеера выходят в 5% «небезопасную» зону** (32dp и 24dp от края при норме 48dp) —
   риск обрезки на телевизорах с overscan (критерий TV-OV).
5. **Нет `KEEP_SCREEN_ON`** на время воспроизведения → риск ухода в Ambient Mode / затемнения (TV-BU).
6. **Баннер лаунчера — вектор 320×180 с розовым фоном и треугольником, без названия приложения**
   (нарушение TV-BN), иконка приложения при этом корректная.
7. **Нет ни одного пустого/ошибочного состояния с действием**: пустой каталог, пустой поиск, отсутствие
   источников — пользователь видит пустой экран или Toast, а не экран с фокусируемой кнопкой.
8. Типографика ниже рекомендованной для 10-foot UI: заголовки карточек 14sp, подписи 12sp
   (`lb_basic_card_title_text_size`/`content_text_size`), подписи секций 12sp с контрастом 4.14:1
   вместо рекомендуемых ≥14sp и ≥4.5:1.

Оценка объёма работ: **P0 — 2–3 дня**, **P1 — 5–7 дней**, **P2 — 2 недели**, **P3 (Compose for TV) — 1–2 месяца**
(раздел 10). P0 закрывает нарушения критериев TV-OV/TV-BU/TV-BN и три системные ошибки дизайна.

## 2. Соответствие требованиям Android TV

Источники требований:
- TV App Quality (Tier 1–3): <https://developer.android.com/docs/quality-guidelines/tv-app-quality>
- TV Design, типографика: <https://developer.android.com/design/ui/tv/guides/styles/typography>
- 10-foot UI, safe zone 5%, контраст, типографика: <https://developer.amazon.com/docs/fire-tv/ja-design-and-user-experience-guidelines.html>

| TV-DP (всё достижимо D-pad) | частично | Навигация реализована, но прогресс-бар плеера `focusable="false"` (`f_tv_player.xml:162`) — перемотка только кнопками/±5 с. |
| TV-DM (нет зависимости от кнопки Menu) | ок | `KEYCODE_MENU` используется как необязательный шорткат (`TvPlayerFragment.kt:657`), основная функция доступна кнопкой «Растянуть». |

## 3. Экран «Главная» (`TvHomeFragment`)

### F-01. Headers включены, но заголовки пустые — 270dp мёртвой колонки
`headersState = HEADERS_ENABLED` (`TvHomeFragment.kt:124`), при этом у двух верхних рядов
`HeaderItem(..., "")` (`:145`, `:156`), а у ряда истории-действий `HeaderItem(2, "")` (`:163`).
Следствия (речь о раскрытом состоянии заголовков — именно оно по умолчанию для `HEADERS_ENABLED` и именно
оно было на экране при замере `[экран]`; Back сворачивает панель):
- колонка заголовков шириной **270dp** (`lb_browse_headers_width`) занимает левый край, ряды начинаются с
  `browseRowsMarginStart = 238dp` (`lb_browse_rows_margin_start`) `[ресурс]`, фактически контент — с 283dp
  (`[экран]`) → **~28% ширины экрана занято подписью из 1–2 слов**, а контента в ряду помещается меньше;
- пустые заголовки дают пустые слоты: на живом дампе `[экран]` над «Новини» виден фокусируемый пустой
  TextView шириной 2px (`bounds [112,329][114,393]`);
- заголовки и ряды в левой колонке не совпадают по вертикали с содержимым, из-за чего фильтры выглядят
  «оторванными» от результатов.

**Рекомендация:** выбрать одну модель навигации:
1. **Простая (быстро):** `headersState = HEADERS_DISABLED`, освободить 238dp — контент получит ~40% больше
   ширины; названия рядов рисовать внутри ряда (`ListRow` с заголовком-«section header»).
2. **Полноценная (правильнее для TV):** оставить headers, но превратить их в реальное меню
   («Главная», «Фильмы», «Сериалы», «История», «Избранное», «Поиск», «Настройки»), а чипы
   фильтров/сортировки перенести в верхнюю панель выбранного раздела. Тогда пустых заголовков не остаётся,
   а колонка получает смысл.

### F-02. Первый контент появляется на 33–40% высоты экрана
`browseRowsMarginTop = 167dp` `[ресурс]`, заголовок приложения — `44sp` в полосе 60dp
(`lb_browse_title_text_size`, `lb_browse_title_height`) `[ресурс]`, кнопка поиска — орб 52dp
(`lb_search_orb_size`). На живом экране `[экран]`: заголовок `[922,54][1808,174]`, чипы на y=177dp и 223dp,
постеры — только с ~260dp из 540dp. Для 10-foot UI это много «хрома» до контента.

**Рекомендация:** кастомный компактный заголовок: название 28–32sp слева, орб 56dp справа, ряды с 96dp;
первые 2–3 ряда видны сразу под заголовком.

### F-03. Пиксели вместо dp в отступах презентеров
`setPadding(32, 16, 32, 16)` — это **пиксели**, значит на 320dpi = 16dp/8dp:
`ContentTypePresenter.kt:26`, `SortCategoryPresenter.kt:22`, `TvActionCardPresenter.kt:21`,
`SiteSearchActionPresenter.kt:25`, `HistoryActionPresenter.kt:20`, `UpdateActionPresenter.kt:20`,
`SearchFilterPresenter` (`TvSearchFragment.kt:45`, 24/12 → 12dp/6dp).
Измерено на устройстве `[экран]`: высота чипа **60px = 30dp** вместо расчётных ~48dp (16sp текст + 16dp
вертикальных отступов). Ниже минимальной цели 48dp, текст «липнет» к краям.

**Рекомендация:** `dp(ctx, 16f)` или `setPadding(dp(horizontal), dp(vertical), ...)`; целевая высота чипа
48–56dp, горизонтальные отступы 24–32dp.

### F-04. «Выбрано» и «в фокусе» неразличимы
`bg_sort_category_selector.xml`: focused = заливка `colorAccent` + обводка 2dp белая; selected = та же
заливка `colorAccent` без обводки. Когда фокус переходит на другой чип, на экране **два** акцентных чипа,
и какой из них применён — непонятно с 3 метров. Дополнительно: у выбранного чипа нет ни галочки, ни
подчёркивания, ни иконки.

**Рекомендация (проверяемая схема):**
- unselected/unfocused: фон `card_dark_bg`, текст `textColorPrimary`, обводка 1dp `colorSeparator`;
- selected/unfocused: фон `#2A2A40`, текст `colorAccent`, слева галочка 16dp, обводка 1dp `colorAccent`;
- focused (любое выделение): белая обводка 3dp + scale 1.05 + elevation, фон не меняется.
Так «применено» и «где я» различаются всегда.

### F-05. Пустые и ошибочные состояния отсутствуют
`setupLoadStateListener()` показывает только `progressBarManager` при `LoadState.Loading`
(`TvHomeFragment.kt:186–196`). Если БД пуста, все ряды пустые, экран — тёмное поле без объяснения и без
действия. Ошибка обновления — Toast `"Ошибка: $errorMsg"` (`:571–577`, строка захардкожена).

**Рекомендация:** единый компонент состояния `TvStateView` (иконка 96dp, заголовок 24sp, описание 16sp,
фокусируемая кнопка 56dp «Обновить данные»/«Повторить»/«Открыть поиск»); использовать на главной, в
деталях, в поиске, в плеере.

### F-06. Порядок рядов: системные действия вперемешку с контентом
Порядок: чипы контента → чипы сортировки → витрина → «Все фильмы» → «Очистить историю» → история →
избранное → «Проверить обновления» → «Поиск на сайте» (`:145–173`). Разрушающее действие
«Очистить историю» — отдельная карточка размером с постер (`HistoryActionPresenter`, отступы 48/24 px).

**Рекомендация:** контент первым (витрина → все фильмы → история → избранное), служебные действия — в
компактный ряд «Ещё»/«Настройки» в конце или в левую навигацию; «Очистить историю» — по `KEYCODE_MENU`
на карточке истории либо в настройках, с подтверждением.

### F-07. Фокус теряется при возврате и при обновлении витрины
`onResume()` → `viewModel.refreshData()` + отложенный `reloadHistory()` (`:108–115`) пересоздаёт
`PagingData`; `updateHighlightRows()` **удаляет и заново добавляет** ряды при каждом эмите
(`:297–317`), из-за чего фокус и позиция скролла могут сбрасываться, а ряды «мигают».

**Рекомендация:** не удалять/добавлять ряды, а обновлять содержимое существующих адаптеров
(`adapter.clear(); adapter.addAll(...)` с теми же `ListRow`, либо `notifyArrayItemRangeChanged`);
сохранять/восстанавливать позицию (`Presenter.ViewHolder` + `setSelectedPosition`) при возврате с деталей.

### F-08. Нет «продолжить просмотр» на карточках истории/избранного
`ViewMovie` (`domain/models/ViewMovie.kt`) не содержит позиции/длительности, поэтому TV-карточки не могут
показать прогресс-бар и «осталось 42 мин», как это делает мобильная история.

**Рекомендация:** добавить в `ViewMovie` поля `positionMs`, `durationMs` (или отдельную модель
`HistoryMovieCard`), рисовать в `MovieCardPresenter` тонкий прогресс-бар 4dp под постером и подпись
«Продолжить с 42:15»; в деталях — на кнопке Play.

### F-09. Два неочевидных входа в поиск
Поиск по БД (`TvSearchFragment`, через орб) и «Поиск на сайте» (`TvSiteSearchFragment`, отдельный ряд-кнопка)
не объяснены пользователю: разница видна только по названию. Легенды/подписи нет.

**Рекомендация:** один экран поиска с двумя вкладками («В каталоге» / «На сайте») на чипах, орб ведёт туда же.

## 4. Экран «Детали» (`TvDetailsFragment`)

### F-10. Действия выглядят как теги, а не как кнопки
`TvActionCardPresenter` рисует `Action` обычным `TextView` с фоном чипа и отступами 32/16 px (`:21`).
«Играть», «В избранное», «Обновить данные» визуально равнозначны и не имеют иконок и приоритета.

**Рекомендация:** Play — primary-кнопка 56dp высотой, с иконкой 24dp, текстом 20sp и подписью
«Продолжить с 00:42:15» или «Смотреть»; вторичные действия — 48dp, текст 16sp, без заливки.

### F-11. Селект сезона/серии/источника нигде не отображается
`TvSourceCardPresenter.onBindViewHolder` жёстко передаёт `selected = false` (`:52`), поэтому ветка
«selected» в `applyState` — мёртвый код (`:96–100`). Пользователь не видит, какой сезон/источник выбран;
единственная подсказка — заголовок блока серий.

**Рекомендация:** пробрасывать реальный индекс выбора в презентер (`SeasonItem.isSelected`,
`SourceItem.isSelected`), рисовать выбранное состояние (обводка 2dp `colorAccent` + галочка) и держать его
при скролле; заголовок блока серий сделать динамическим: «Серии · Сезон 3».

### F-12. Постер деталей апскейлится
`POSTER_WIDTH = 274`, `POSTER_HEIGHT = 400` (`:64–65`) — передаются в `Glide.override(...)`, то есть в
**пикселях**, а область постера в `FullWidthDetailsOverviewRowPresenter` — `274dp` по высоте
(`lb_details_overview_height_large`) `[ресурс]`, т.е. 548px при 320dpi. Итог: картинка растягивается ~2×,
на 4K-панели — тем более.

**Рекомендация:** грузить с `override(dp(274), dp(400))` и `downsample(DownsampleStrategy.CENTER_OUTSIDE)`,
либо в 2× от dp-размера для 4K (`TV-4K`).

### F-13. Источники подписаны технической строкой
`createSourceItem` формирует `"HD • host • HLS"` (`:520–540`). Для пользователя важны разрешение и
«запасной вариант», а не хост.

**Рекомендация:** «1080p · HLS» / «720p · MP4», иконка HD-бейджа, подпись «по умолчанию» у выбранного;
хост — только в детальном экране/логе.

### F-14. Строка прогресса обновления живёт внутри контента
`addUpdateProgressRow()` вставляет ряд на индекс 1 (`:150–160`), а клик по карточке **отменяет** обновление
(`onCancelUpdateRequested`). Отмена по клику на карточку прогресса — скрытое разрушающее действие.

**Рекомендация:** индикатор прогресса — в шапке (или в action-баре рядом с «Обновить»), отмена — только
явной кнопкой «Отменить» с подтверждением.

### F-15. Типографика описания не адаптирована под TV
Сабы `TvDetailsDescriptionPresenter` собираются из строки с `КП:`, `IMDb:`, `👍/👎` (`:86–104`), лимит
`maxLines=6` задан в теме (`themes.xml:110`), размеры текста — дефолтные Leanback. Пять строк метаданных
подряд на 10-foot экране читаются плохо.

**Рекомендация:** метаданные — в 2 строки максимум: «2024 · Сериал · 3 сезона · 24 серии» и
«★ 7.8 IMDb · ★ 7.1 КП»; описание — 16sp/24sp line-height, максимум 4 строки с «…».

## 5. Плеер (`TvPlayerFragment`, `f_tv_player.xml`)

### F-16. Нет индикатора буферизации
`showLoading(show: Boolean)` — пустой метод с комментарием «можно добавить» (`:1101–1103`). Штатный
`iv_buffering` из `PlayerView` работает только по атрибуту `show_buffering="when_playing"`
(`f_tv_player.xml:20`) и только при `playWhenReady`, а `use_controller="false"` убирает остальную
индикацию. При паузе, перемотке и переключении качества пользователь не видит никакой реакции.

**Рекомендация:** собственный индикатор: круг 48dp + текст 16sp «Загрузка…» по центру, порог показа
300 мс; для перемотки — «−10 c» / «+10 c» с текущим временем.

### F-17. Оверлей выходит в небезопасную зону (TV-OV)
`controlsGroup`: `paddingStart/End = 32dp`, `paddingBottom = 32dp` (`:131–134`);
`btnAspectRatio`: `marginEnd = margin_big = 24dp` (`:73–74`, `f_tv_player.xml:259`); `btnBack` — 32dp слева.
При 960×540dp безопасная зона — 48dp по горизонтали и 27dp по вертикали `[док]`.

**Рекомендация:** все края оверлея — ≥48dp; топ-кнопки (`btnQuality`, `btnAspectRatio`) выровнять по одной
базовой линии и по 48dp от правого края; кнопки 64dp (сейчас 56/64/72dp вперемешку), иконки 28dp.

### F-18. Прогресс-бар нельзя «взять» пультом
`SeekBar ... android:focusable="false"` (`f_tv_player.xml:162`) — скраббинг недоступен, только шаги.
`SEEK_STEP_MS = 5_000L` (`TvPlayerFragment.kt:59`) — для TV это мало (стандарт 10 с), и нет визуального
подтверждения прыжка.

**Рекомендация:** либо сделать прогресс фокусируемым (в фокусе — «ручка» 24dp, шаг 5%/нажатие, превью
времени), либо оставить `focusable=false`, но добавить аккумулятивную перемотку: удержание/серия нажатий
в течение 1 с суммируется (±10/20/30 с), с оверлеем «−30 c → 00:12:04».

### F-20. Конец серии без предупреждения

### F-21. Ошибка — сырой текст без действий

**Рекомендация:** экран ошибки по шаблону: иконка, «Не удалось воспроизвести», человекочитаемая причина

### F-22. Диалоги — телефонные `AlertDialog`

белая рамка фокуса 3dp, кнопка «Закрыть» внизу; либо `GuidedStepSupportFragment` для выбора источника/сезона.

### F-23. Нет управления дорожками и скоростью

## 6. Поиск и «Поиск на сайте»

### F-26. Нет пустого/загрузочного состояния в поиске
`TvSearchFragment` всегда рисует ряд фильтров и ряд результатов (`:81–95`); при пустом результате — пустой
экран без подсказки. У ряда фильтров заголовок `""` (`:85`) — снова пустой слот в headers.
Минимальная длина запроса 2 символа (`:139–143`) не объясняется пользователю: ввод одной буквы «ничего не
делает».

**Рекомендация:** «Введите минимум 2 символа» под строкой поиска; «Ничего не найдено — изменить запрос /
искать на сайте» с фокусируемой кнопкой; спиннер 32dp в правом верхнем углу при загрузке;
`HeaderItem("Фильтр")` вместо пустого.

### F-27. «Поиск на сайте» без индикации сохранения карточки
`TvSiteSearchFragment` по клику вызывает `viewModel.openItem(it)` — сохранение в БД и переход; на время
сетевой операции нет ни прогресса, ни блокировки повторного клика; пустой результат — только Toast.

**Рекомендация:** прогресс на карточке (или общий индикатор), отключение клика на время операции,
пустое состояние с кнопкой «Повторить».

## 7. Системные интеграции и оболочка

### F-28. Баннер лаунчера без названия (TV-BN)

**Рекомендация:** `onBackPressedDispatcher.addCallback { ... }` + `popBackStack()`, диалог выхода — на TV-стиле.

### F-31. Нет Watch Next и глобального поиска

**Рекомендация (P2):** Watch Next-канал с 3–5 последними фильмами (обновление из `HistoryInteractor`),
searchable-активити с `LEANBACK_LAUNCHER`, обработка `ACTION_VIEW` (сейчас `TvMainActivity.handleSharedUrl()`

### F-32. Нет локализации TV-строк

## 8. Дизайн-токены: что есть и что предлагается

### 8.1 Типографика

с реальным фокусом; двойная рамка (5dp + 2dp) перегружена; у чипов фокус-рамка 2dp — тонко для 3 м.

| P2-7 | Определение TV: `FEATURE_LEANBACK || FEATURE_TELEVISION || UI_MODE_TYPE_TELEVISION` | Мобильный UI не запускается на ТВ-боксах | S |
| P2-8 | Дорожки/субтитры/скорость в плеере | Диалог «Аудио / Субтитры / Скорость», выбор сохраняется | L |

### P3 — единая дизайн-система на Compose for TV (7–10 дней по TV-части)

Проверено разово (2026-10-20) и **откачено**: `androidx.tv:tv-material:1.0.1` собирается на текущем
тулчейне (Compose 1.6.8, `compileSdk 34`), пробный экран рендерится и получает D-pad-фокус. В рабочем
коде зависимостей Compose for TV нет (BOM 2024.02.02). Детальный план фаз и рисков —
[TV_COMPOSE_MIGRATION.md](TV_COMPOSE_MIGRATION.md). Порядок: дизайн-система → Главная →
Детали → оверлей плеера → поиск/«Моё» → удаление Leanback. Миграция на Media3 и на `tv-material 1.1.0`
(Kotlin/AGP/compileSdk) — отдельные задачи. Плюсы: токены из раздела 8, единая фокус-модель, превью;
риски: восстановление фокуса, Paging/Glide в Compose, смешение стеков на переходном этапе.

## 11. Критерии приёмки (общие)

1. **Геометрия:** все интерактивные цели ≥48dp; края ≥48dp по горизонтали и ≥27dp по вертикали; шаг
   карточек в ряду = `tv_card_width` + 16dp.
2. **Типографика:** нет текста <14sp, кроме бейджей 12sp; контраст ≥4.5:1 (кроме декоративных ≥3:1);
   в кадре не более 2 строк описания.
3. **Фокус:** в любой момент на экране ровно один фокус, видимый с 3 м; состояние «применено» отличимо от
   фокуса; после возврата на экран фокус на прежнем элементе.
4. **Состояния:** каждый экран имеет loading / empty / error с действием.
5. **Плеер:** видимая реакция на буферизацию, перемотку и смену качества; ошибка с «Повторить»;
   `KEEP_SCREEN_ON` при воспроизведении.
6. **Соответствие:** TV-OV, TV-BU, TV-BN, TV-DP, TV-PC, TV-PP — «ок» по чек-листу раздела 2.

## 12. Как проверять (эмулятор)

Стенд: `emulator-5554`, Android TV 1080p, 1920×1080, density 320 (`wm size`/`wm density` → 960×540dp).

```bash
export PATH="$PATH:$LOCALAPPDATA/Android/Sdk/platform-tools"
export MSYS_NO_PATHCONV=1                     # иначе /sdcard/... превращается в путь Git Bash

adb -s emulator-5554 shell am force-stop com.arny.mobilecinema.debug
adb -s emulator-5554 shell am start -n com.arny.mobilecinema.debug/com.arny.mobilecinema.presentation.splash.StartActivity
adb -s emulator-5554 exec-out screencap -p > shot.png
adb -s emulator-5554 shell uiautomator dump /sdcard/ui.xml && adb -s emulator-5554 pull /sdcard/ui.xml ui.xml

# D-pad
adb -s emulator-5554 shell input keyevent 20   # DOWN
adb -s emulator-5554 shell input keyevent 22   # RIGHT
adb -s emulator-5554 shell input keyevent 23   # CENTER
adb -s emulator-5554 shell input keyevent 4    # BACK
adb -s emulator-5554 shell input keyevent 85   # MEDIA_PLAY_PAUSE
```

Проверять вручную (сценарии приёмки):
1. Запуск → первый контент виден без прокрутки; фокус на первой карточке витрины.
2. Переключение чипов: видно, что применено, и где фокус; после выхода и возврата фильтр сохранён.
3. Детали: Play с «Продолжить с…»; смена сезона — выбранный сезон отмечен; источники читаемы.
4. Плеер: пауза/перемотка/качество; ошибка источника → «Повторить»; конец серии → отсчёт.
5. 30 минут воспроизведения → экран не гаснет.
6. Пустая БД (`adb shell pm clear`) → пустое состояние с кнопкой, а не пустой экран.
7. Лаунчер → баннер с названием приложения.

## 13. Что не проверено / риски

- **`TvDialogTheme.windowNoTitle=true`** — предполагаю, что заголовки диалогов не отображаются; нужен
  скриншот диалога на устройстве.
- **Predictive back** (`enableOnBackInvokedCallback`) на API 34 в сочетании с переопределённым
  `onBackPressed()` — поведение не проверялось.
- **Живой APK на эмуляторе** — `1.6.4-DEBUG`, установлен 2026-10-20 05:02, то есть **старше текущих
  исходников** (правки в `TvHomeFragment`/`TvDetailsFragment` от 08:00–10:00). Скриншоты и замеры
  геометрии отражают установленную сборку, а не HEAD; после пересборки часть цифр (размеры карточек,
  наличие подписей у карточек) может отличаться.
- **Навигация D-pad по всем экранам** в этой сессии не прогонялась (только чтение кода и дамп главной).
- **Контрасты на реальной ТВ-панели** не измерялись (расчёты WCAG — только для sRGB).
- **Производительность** (jank при скролле рядов с Glide, размер картинок) не профилировалась.
- **Compose for TV** в проекте отсутствует: оценка миграции P3 сделана по объёму TV-экранов, без прототипа.
