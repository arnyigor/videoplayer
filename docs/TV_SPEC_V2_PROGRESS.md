## Найденные и исправленные дефекты

1. **TV-плеер никогда не восстанавливал позицию**: `PlayerViewModel.setPlayData()` не вызывался, поэтому
   `uiState.movie` оставался `null`, `saveMoviePosition()` молча ничего не сохранял, а `playSerial` всегда
   стартовал с `position = 0`. Теперь позиция резолвится до старта, а при ошибке чтения истории плеер
   получает состояние с нулевой позицией вместо вечного ожидания.
2. **Прогресс писался по индексу плейлиста**, а не по серии: при пропуске серии без URL сохранялась чужая
   пара `(season, episode)`. Теперь источник истины — `mediaId`/`PlayableRef`.
3. **`showLoading()` был пустым**, `KEEP_SCREEN_ON` на TV отсутствовал.
4. **Строки вперемешку с кодом**, размеры карточек в пикселях, баннер без названия.
5. **Жанры каталога грузились ~1 минуту на устройстве** (срез 7): `GenreSearchHelper.toDisplayGenres`
   нормализовал каждый алиас каждой группы заново для каждой из 4520 строк `genre` — ~1.1 с на прогретом
   JVM и десятки секунд в debug-сборке на эмуляторе. Добавлен `toCanonicalGenres` с предварительно
   нормализованными алиасами: 1.1 с → 20 мс при том же результате (39 жанров, список совпал побайтно).
6. **В чипах фильтра были мусорные «жанры»** из БД (`12+`, имена актёров): теперь показываются только
   канонические жанры из `GenreSearchHelper`.
7. **Плеер уходит на чужую серию при сбое потока** (срез 8, не исправлено): после запуска S01E01
   с мёртвым URL плеер перебрал серии и записал прогресс на S01E06 — CTA деталей стал
   «Продолжить S01E06» с 1 %. ТЗ §8.2 запрещает такую подмену; чинить в PLR/PLY (плеер, не экран деталей).
8. **Hero «Смотреть» открывал детали вместо плеера** (срез 9, исправлено): `onPrimary` вёл в
   `actionToDetails`. Теперь `onPlay` → `actionToPlayer` с `movieId`, позицию/серию резолвит сам плеер.
9. **Серая плашка под постером в карточке «Продолжить»** (срез 9, исправлено) — у текстового блока
   не было фона, просвечивал светлый `surface` темы; добавлен `background(TvColors.Surface)`.

### Runtime на эмуляторе Television_1080p (API 34)

- Приложение запускается, каталог загружается, карточки и фокус рисуются.
- **Найден и исправлен блокирующий дефект миграции**: `MIGRATION_7_8` создавал уникальный индекс
  `(profile_id, playable_id)` до backfill, когда у всех старых строк `playable_id = ''` →
  `SQLiteConstraintException` и падение при старте. Индекс перенесён после `UPDATE`; повторный запуск
  на той же v7-базе прошёл успешно.
- CTA деталей показывает `Смотреть S01E01` (резолвер подключён).
- Плеер открывается, видны индикатор буферизации и `Сезон 1 • Серия 1`.
- Поток на эмуляторе не играет (мёртвые URL), поэтому проверен путь ошибки. Попутно найден
  **бесконечный цикл ретраев**: исключённые URL использовались как fallback. Теперь исключённые
  источники пропускаются, а недоступная выбранная серия даёт панель ошибки, а не тихий переход.
- Панель «Следующая серия» в runtime не проверена: для неё нужно дойти до конца эпизода.

## Риски

- Миграция БД необратима: перед релизом с v8 нужен тест на копии реальной БД и предупреждение в релиз-нотах.
- Мобильный плеер пока пишет прогресс по старой схеме (`played_ms` + `history`); расхождение исчезнет в `PLY-02`.
- `PlaybackProgressStore.record` пишется в `NonCancellable` из process-scope — это осознанно, но требует
  проверки на устройстве, что выход из плеера не теряет последнюю секунду.
- Каталог не использует Paging3: страницы грузит ViewModel (`loadMore` + `CatalogPaging`). Это убрало
  подъём paging/coroutines-зависимостей, но `TST`-покрытие пагинации теперь только unit (редьюсер).
- Instrumentation-тесты в проекте привязаны к release-варианту (`testBuildType = "release"`), а release
  требует настроенной подписи, поэтому `connectedReleaseAndroidTest` локально не запускается. Пока это
  блокирует `Migration7To8Test` и UI-тесты фокуса; чтобы их запускать, нужно перевести `testBuildType`
  на debug или настроить подпись в CI.
